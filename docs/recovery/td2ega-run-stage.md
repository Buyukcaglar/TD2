# Bounded run/block byte-producing stage

`FN-EGA-000169`, far entry `06C9:6B02`, and its ordinary near helpers `FN-EGA-000170` (`6B97`) and `FN-EGA-000171` (`6C6E`) map to one [C17 export](../../src/recovered/td2ega_run_stage.c) and [bounded pool API](../../src/recovered/td2ega_run_stage.h). [Build evidence](evidence/td2ega-run-stage-build-v1.json) and [848 composed comparisons](evidence/td2ega-run-stage-validation-v1.json) cover actual original instructions and actual7030 paragraph moves. The local helpers share their caller's BP frame; they are not separate native exports or arbitrary-entry prototypes.

The admitted profile requires original DS=SS, an ordinary exclusive byte pool disjoint from code/stack/result, a nonwrapping twenty-byte source prefix, and **one through eleven marker entries**. The original copies sixteen bytes starting at source4 into parent-frame locals; only eleven source marker bytes fit that copy. Larger counts read onward into saved registers, BP and argument words during rank construction. Those stack-dependent inputs are outside the native profile; proving actual resource/caller domains remains a phase1/2 obligation. No supplied resource has been decoded or admitted by these tests.

Control values above80h skip the first stage. Otherwise6C6E expands marker-delimited blocks, reports their produced byte count, and6B02 moves rounded paragraphs to the allocation tail before its run stage. Repeat-byte0 makes256 total block copies, and1 makes257, due to the original do/while decrements. Control1 takes an early near return with AX equal to the declared header's high byte and DX=1, without first-stage output. A fixture verifies reported65,536/no first writes, its paragraph move and131,072 later literal writes. These effects remain explicit rather than replaced by conventional repeat/count semantics.

The run stage builds a byte-to-rank table; duplicate markers use the last rank. Rank1 takes an eight-bit repeat count, rank3 a sixteen-bit count, other nonzero ranks repeat the following value `rank-1` times, and unranked bytes copy literally. Zero run counts consume their token while writing nothing. Literal countdown and token SUB/SBB differ at a zero low word; the C preserves the separate low/high counter operations.

Pointers normalize only at the outer loop when offset is greater than8000h. A long REP run can wrap a sixteen-bit destination offset before that check and rewrite the beginning of the same segment. Inner block copies likewise do not rebase mid-loop. The native code retains data segment/offset views and byte order; it is a recovered byte algorithm, not an instruction interpreter or an automatic linear decompressor. The whole-pool comparisons include a65,535-byte run followed by a write that returns to offset0.

Far return is AX=0/DX=the destination segment. The destination-offset argument is ignored, and the source argument pair is changed to the table-skipped source or relocated intermediate source. DS/SI/DI/BP/SS are restored and DF is clear. Near helpers use parent BP locals and return with RET; the outer function uses RETF with ten caller-cleaned argument bytes. The run helper's computed count is immediately overwritten by the far wrapper, so the C folds that unused child return into its parent operation while recording actual byte writes separately.
