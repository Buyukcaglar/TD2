## Result

No substantive evidence, phase-order, observation or arithmetic blocker was found. The draft correctly selects ten decision groups: six original-body groups covering the eleven sampled original entries, plus scalar memory, guarded signed division, canonical loader and explicit-profile path adapters. It does not count any selected original entry as newly recovered, import a whole source file, approve a distributable, replace the independent raw/bus oracle or close whole-core/gameplay/fidelity gates.

The explicit restrictions requested by the boundary review are present:

- Four live-SS argument alias cases remain observed mismatches outside the native profile.
- RPM admission is memory effects with `NULL,NULL` output pointers; its bool return and non-NULL pointer/neutral-clutch consumers are excluded.
- The transitive drag/brake path is gear zero, with no general independent brake admission.
- RLE admission is the exact run-only branch, escape controls 81/83/8B hex and synthetic fixture locations. Sequence-first, `rle_seq_pass`, `paras_of` and `far_move_up` are not credited merely because they appear in the surrounding file or instruction fence.
- EGA hardware/latch/display behavior is excluded from RAM-point/clip admission.
- Scalar typed-lvalue/bulk portability, signed-division remainder outputs and raw CPU fault ABI remain excluded.
- Loader support accepts the exact canonical packed EXE; identity rejection is not presented as deep parser fuzz coverage.
- Profile-path support is an explicit Windows fixture domain, with default preference-directory/CLI integration, concurrent replacement races and quiet-write return ambiguity excluded.

The origin manifest retains the pinned MIT notice, candidate-file hashes, exact upstream commit/blob identities through the normative decisions, the local change receipt and patch, and the derived origin of `host_paths.c`. Original media/game-text blockers remain outside distribution admission.

## Dependency clarification before extraction

The selected source is not a ready-to-copy standalone extraction bundle. At draft review, KRU-07's range `mem.h:32-40` includes `mp` and `wr8`, while its symbol list did not name them. Other selected functions transitively use `ds_far`/`ds_far_wr`, far-pointer constructors/readers/writers and `row_at`. The parent was asked to make those dependencies explicit as exercised dependencies only, or state clearly that final extraction dependency closure remains an integration obligation. No skipped RLE helpers should be added by that clarification.

This is a clarity/closure condition for a future extraction, rather than evidence that the already-tested DLL failed. The draft's rules already require fresh dependency review, build and comparison for moved code, and explicitly prohibit inheritance of standalone helper acceptance from a header dependency.
